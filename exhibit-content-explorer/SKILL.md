# 深入探索展项内容

把原始展陈文档转化为可追溯的展项清单与可讨论的深化方案。默认中文输出；沿用原文的名称、层级和排序。用户仅要求提取时只做提取；要求深入探索时覆盖每项，不自行挑选少数项替代全量工作。

## 1. 建立文档与提取基线

先读取 [文档提取与定位](references/extraction.md)。记录文件、版本、可读范围、分页口径和缺失信息。使用现有文档解析、PDF 渲染、表格工具；若环境提供对应文件 Skill，按实际格式读取其操作说明。不要把解析成功等同于完整阅读。

重点检索：**重点、要点、多媒体、视频、互动、知识拓展、声光电、交互**。逐页或逐工作表扫描全部内容，包括表格、文本框、批注等有意义的内容区域；图片中的文字需 OCR 并核对。补充语义检索可发现同义表达，但必须标为“语义补充”，与直接关键词命中区分。

关键词是入口，不是截取边界：按标题层级、展项编号、段落关系和表格结构恢复完整展项，包含相关说明、脚本、子项、技术描述和注释。先交付原文清单，再开展研究；清单较长时分批输出并维护完成状态。

## 2. 可靠研究

先读 [按需研究路由](references/research-routing.md)，为当前展项选择最轻且足够的研究模式：无外部检索、快速核验、深度研究或文献综述。不要因为搜索 Skill 或工具可用就全部调用；只有当前证据缺口、争议程度、时效要求或决策风险满足升级条件时，才增加研究深度。

对每项回答是什么、背景、机制或过程、与文档主题的关系、易误解之处。研究新增事实时优先采用博物馆、政府、学术机构、论文、档案及相关组织的原始材料；给出支持具体结论的链接与定位。搜索结果摘要只用于发现来源，关键结论需要打开原始页面或全文核对。工具不可用或证据不足时标为待核实，不把推断写成事实。

区分四种内容：**原文、已核实事实、策划解读、创意建议**。原文也可能有错误：保留原文，另列核查结果及分歧。年代、人物、比例、因果关系、文化归属等关键事实必须有证据；来源冲突时说明口径。不要为展项编造历史、参数或观众效果。

## 3. 内容与体验深化

先读 [展项深化工作法](references/deepening-workflow.md)，判断当前任务适合直接深化、引导澄清还是多方案比较。再按 [深化框架](references/development.md) 审视每项：学习价值、社会与精神意义、讲述方式、物理形式、体验机制、参与学习、传感器映射、空间关系。各维度都需要判断，但不强迫每项使用所有技术；不适用时解释原因。

深化前先回写对这一项的理解：**内容内核、目标观众、希望发生的认知变化、已有约束、尚未证实的假设**。已有材料能够回答的内容直接采用，不重复询问。只有某个缺失信息会实质改变方向时，才一次提出一个聚焦问题；提问从最高不确定性开始。

从内容中的真实动作、对象、关系和变化寻找交互。每个推荐方案写清：**学习目标 → 观众动作 → 系统判断 → 可感知反馈 → 所学结论**，并指出哪部分是展示简化。技术形式要帮助理解具体内容。

开放型展项先提出 2–3 条有本质差异的方向，说明各自的内容优势、体验取舍、空间条件与实施风险，并给出推荐理由。方向应来自同一个内容内核，但可分别以叙事、实物动作、数据变化或空间沉浸为主；不要只替换屏幕尺寸、传感器或视觉风格来凑方案。用户已经明确方向，或只有一个方向符合事实与条件时，不机械发散。

方案按复杂度分段呈现：先确认内容内核与学习目标，再说明体验路径、媒介与空间，最后说明验证方法。互动协作中可让用户逐段纠偏；用户要求一次性报告或文档很长时，完整给出并把关键决策、假设和待选择项集中列出，避免频繁打断。

在缺少预算、空间、客群等条件时，可先给概念方案并列出假设与待确认条件；不要因此停止已经能完成的提取和研究。跨展项可提议联动，但保留每项独立来源与学习目标。

## 4. 交付与检查

使用 [输出模板](references/output-template.md)，交付文档说明、完整提取清单、逐项深化卡、来源和待核实事项。默认在聊天中交付；用户指定文件格式时再按该格式制作。不要因为文档长而只给摘要或隐去未完成项。

结束前检查：

- 每个关键词命中均映射到展项、合并项或有理由的排除项；语义补充单独标记。
- 原文完整性与跨页边界已核对，清单摘要不替代完整原文。
- 页码口径明确，未确认页码没有被当作真实页码。
- 所有展项均有处理状态；事实、解读和创意能被区分。
- 新增关键事实有可查来源，互动动作与学习结果有直接联系。
- 研究模式与问题风险匹配；没有为了“显得深入”而执行无关搜索或堆积文献。
- 深度研究有子问题和停止条件；文献综述按主题比较共识、分歧、证据质量与空白，不按论文逐篇堆叠。
- 每项能看出“当前深化层级、推荐方向、为何推荐、下一步验证什么”。
- 多方案之间存在真正的体验逻辑差异，取舍标准与内容目标一致。
- 工程条件和展示简化已说明；未实际验证的方案不写成已验证效果。
